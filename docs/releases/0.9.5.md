# LCU 0.9.5 (DRAFT)

> Draft. The release owner fills in the placeholders marked TODO (source commit, checksums, gate results) before publishing.

**Adds a local diagnostic log so a hung `js` call can be explained.** In Claude Code, `js` calls once hung until the 120 s MCP timeout and worked again later, and nothing recorded what the relay was waiting on. The adapters now write a metadata-only log of each call and approval. Everything else is as in [0.9.4](https://github.com/amontlabs/lcu/blob/v0.9.5/docs/releases/0.9.4.md). Windows remains deferred.

## Changes

- **Diagnostic log.** The Claude Code relay and the shared client (Pi, Oh My Pi, Hermes) write one JSON-lines file per process under `~/Library/Logs/LCU/` (macOS) or `${XDG_STATE_HOME:-~/.local/state}/lcu/logs/` (Linux). It records when each call started and ended and how (ok, tool error, timeout, aborted), whether an approval was opened and for which app, whether the `lcu-approve` mod claimed it, and the choice. It never records tool arguments, results, approval messages, UI text, error text or session ids.
- **Strict retention.** Files older than 7 days are deleted when an adapter starts, the oldest are deleted past 20 MiB in total, and one process stops writing at 2 MiB. `LCU_DIAGNOSTIC_LOG=0` turns the log off and `LCU_LOG_DIR` moves it. Files never leave the computer.
- **`lcu status --json`** has a `diagnostic_log` object, and `lcu status` and `lcu doctor` print the directory and policy.
- Docs: [diagnostic log](https://github.com/amontlabs/lcu/blob/v0.9.5/docs/ADAPTERS.md#diagnostic-log).

No runtime, tool schema, instruction or input behavior changed, and no new tested app pairs are claimed.
